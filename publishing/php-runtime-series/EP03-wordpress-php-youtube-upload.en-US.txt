--- DESCRIPTION START ---
WordPress and PHP have separate update paths. Updating WordPress does not, by itself, confirm that PHP's security fixes are installed.

Check your site:
1. Open Tools > Site Health > Info > Server and note the PHP version.
2. Ask your hosting provider or server administrator to confirm the package build and security fixes used by your live site.
3. Before a PHP upgrade, back up and test WordPress, theme and plugin compatibility.
4. Afterward, verify the PHP actually serving requests and test the site's main functions.

Vendors may backport security fixes into older packages. A version number alone is not a verdict; check the vendor's advisory and full package version. Managed hosting may handle these updates for you.

FACT-CHECK NOTES
- A WordPress-core update indicator does not certify plugin, theme or PHP patch status.
- Site Health is an information screen; it does not upgrade PHP.
- A vendor package may contain backported fixes. Do not infer exposure solely from the upstream-looking version number.
- Check the running website's PHP, not only a command-line PHP binary or the container host.
- Patching alone does not establish that a site was never compromised.
- The WordPress PHP update guide contains older version recommendations; this film uses its maintenance workflow, not those historical version numbers.
